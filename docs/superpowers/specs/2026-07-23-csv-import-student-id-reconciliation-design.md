# CSV 匯入與學員 ID 調整設計

## 目標

本功能同時處理兩個相關需求：

1. 一般學員資料編輯視窗允許修改既有學員 ID，並安全同步其報名關聯。
2. 季度 CSV 的學員編號空白時，以「姓名＋性別＋出生日期」判斷是否為既有學員；唯一符合時更新既有資料，沒有符合時才自動建立新 ID。

系統以資料庫為最終判定者。前端提供即時驗證與匯入預覽，但所有 ID 修改、身分比對及自動配號都必須在資料庫交易內再次驗證。

## 範圍

包含：

- 一般學員資料編輯視窗的 ID 編輯。
- 手動新增學員的 ID 驗證。
- 季度 CSV 解析、預覽分類及資料庫匯入。
- 學員 ID 與報名外鍵的同步更新。
- 對應的前端、服務層及資料庫測試。

不包含：

- 自動遷移既有非數字 ID。
- 合併兩位使用不同 ID 的既有學員。
- 在 CSV 匯入預覽中手動編輯 ID。
- 修改 CSV 檔案本身。

## 學員 ID 規則

### 新增與修改

- 手動新增學員、修改既有 ID，以及 CSV 中有填寫的學員編號，都必須是大於 `0` 的整數。
- 驗證以字串進行，不使用 JavaScript `Number`，避免大整數精度問題。
- 前後空白會移除。
- 前導零會正規化，例如 `0012` 轉成 `12`。
- 空字串、`0`、負數、小數、英文字母及混合字元都拒絕。
- CSV 的學員編號欄位可以空白；空白代表啟用身分比對與自動配號流程。

### 既有非數字 ID

- 資料庫中既有的非數字 ID 暫時保留。
- 既有非數字 ID 未改號時，仍可更新姓名、聯絡方式等其他欄位。
- 一旦使用者修改該 ID，新值就必須符合正整數規則。
- 新增資料及 CSV 指定 ID 不再接受非數字 ID。

## 一般學員資料編輯

### 使用者介面

- `StudentEditForm` 的「學員編號（唯讀）」改為可編輯的「學員編號」欄位。
- 欄位使用文字輸入並設定數字鍵盤提示，避免瀏覽器數字欄位自動轉換或允許小數。
- 欄位旁顯示規則：「僅限正整數，前導零會自動移除」。
- 儲存前先正規化 ID；格式錯誤時留在表單並顯示中文錯誤。
- ID 有變更時顯示確認訊息：「修改學員編號將同步更新所有報名紀錄」。
- 未修改 ID 時維持既有編輯流程的操作感受。

### 原子儲存

- 新增資料庫 RPC，在單一交易內更新學員 ID 與其他表單欄位。
- RPC 參數包含原始 ID 與完整、明確白名單化的學員欄位，不接受任意資料表欄位。
- RPC 必須：
  - 驗證呼叫者角色為 `editor` 或 `admin`。
  - 鎖定原始學員列。
  - 確認原始學員仍存在。
  - 正規化及驗證新 ID。
  - 確認新 ID 未被其他學員使用。
  - 在同一個 `UPDATE` 中更新 ID 與其他欄位。
  - 回傳更新後的完整學員資料。
- `enrollments.student_id` 外鍵改為 `ON UPDATE CASCADE ON DELETE CASCADE`，因此學員 ID 變更時報名紀錄會在同一交易內同步改號；課程仍透過 enrollment ID 保持關聯。

### 前端選取狀態

- 服務層回傳 RPC 更新後的學員資料。
- 儲存成功後，學員詳情視窗立即以回傳資料取代目前選取學員，再重新整理全域資料。
- 選取狀態不可繼續以舊 ID 查找，避免改號後視窗顯示過期資料或報名紀錄消失。

## 手動新增學員

- `AddStudentModal` 套用相同的正整數驗證與前導零正規化。
- 自動建議 ID 仍以現有數字 ID 的最大值加一計算。
- 新增前在前端驗證；資料庫仍執行最終驗證與主鍵唯一性檢查。
- 重複 ID 顯示「學員編號已存在」。

## CSV 身分比對

### 正規化

CSV 學員編號空白時，使用以下三欄建立身分比對鍵：

- 姓名：移除前後空白後比對。
- 性別：移除前後空白後完全相同。
- 出生日期：正規化為 `YYYY/MM/DD` 後比對。

只有三欄都有值且正規化後全部相同，才視為同一位學員。任一欄空白或不同，都不成立既有學員比對，該列進入新增與自動配號流程。

手機電話不再參與空白 ID 的身分判定。

### 分類規則

對每一列學員編號空白的 CSV：

1. 資料庫沒有符合者：
   - 以目前最大數字學員 ID 加一建立新學員。
   - 將來源列與新 ID 加入 `assigned_ids` 回傳。
2. 資料庫唯一符合：
   - 使用該既有學員 ID。
   - 更新學員資料及該季度報名。
   - 學員更新欄位遵循既有規則：CSV 有值時覆寫，CSV 空白時保留資料庫原值。
3. 資料庫有兩位以上符合：
   - 擲出帶有來源列的明確錯誤。
   - 整次匯入 rollback。

同一份 CSV 中若有兩列空白 ID 且三欄身分鍵相同，前端解析、預覽分類及資料庫 RPC 都必須阻擋，不自動合併兩列。

### CSV 有指定 ID

- 指定 ID 先套用正整數驗證與前導零正規化。
- 資料庫已有該 ID 時更新學員。
- 資料庫沒有該 ID 時，以指定 ID 建立學員。
- 同一份 CSV 重複指定相同 ID 時維持整批阻擋。

## 匯入預覽

### 前端分類

- `loadImportPreview` 繼續載入完整、分頁化的學員與報名快照。
- `classifyImport` 使用與資料庫相同的三欄正規化規則。
- 預覽產生列級解析結果，但不修改送往資料庫的原始空白 `provided_student_id`。
- `payload` 保留原始意圖，資料庫送出時重新比對，避免預覽後資料變更造成錯誤。

### 顯示內容

匯入預覽增加：

- 更新學員數量。
- 新增學員數量。
- 空白 ID 列的解析結果，例如：
  - `來源第 2 列：王小明 → 更新學員 398`
  - `來源第 3 列：陳美麗 → 新增並自動指派編號`

多人符合及同檔案重複身分鍵顯示於錯誤區，並停用「確認匯入」。

### 最終判定

- 預覽只提供使用者確認。
- `import_season_data` 在交易內重新驗證指定 ID、空白 ID 身分鍵、多人符合、同檔案重複及自動配號。
- 匯入 RPC 保留 advisory transaction lock，確保同時進行的 CSV 匯入不會取得相同新 ID。
- 任一列失敗時，學生、報名及課程全部 rollback。

## 資料庫變更

新增 migration，包含：

1. 重建 `enrollments.student_id` 外鍵，加入 `ON UPDATE CASCADE` 並保留 `ON DELETE CASCADE`。
2. 新增學員 ID 驗證 trigger：
   - 新增學生時驗證並正規化 ID。
   - 更新 `student_id` 時驗證並正規化新 ID。
   - 其他欄位更新且 ID 未變時，不阻擋既有非數字 ID。
3. 新增原子學員資料更新 RPC。
4. 完整重述並更新 `import_season_data(jsonb)`：
   - 指定 ID 的正規化與驗證。
   - 空白 ID 的嚴格三欄比對。
   - 唯一符合時更新既有 ID。
   - 無符合時自動配號。
   - 多人符合與同檔案重複身分鍵的錯誤。
5. 所有 RPC 使用 `security definer`、空 `search_path`、明確授權與 `current_app_role()` 權限檢查。

## 錯誤處理

服務層將資料庫錯誤轉成下列使用者訊息：

- 重複目標 ID：`學員編號已存在`
- 非法 ID：`學員編號必須是大於 0 的整數`
- 原始學員不存在：`找不到要更新的學員，請重新整理`
- CSV 多位學員符合：`姓名、性別、出生日期符合多筆資料，請先整理資料庫`
- CSV 同檔案重複身分：指出目前來源列及首次出現的來源列

錯誤必須保留既有表單內容及未儲存狀態，讓使用者可以修正後重試。

## 測試策略

### Domain 單元測試

- 正規化 `0012` 為 `12`。
- 拒絕空白、`0`、負數、小數、英文字母及混合字元。
- CSV 空白 ID 可解析；CSV 有值 ID 必須符合正整數規則。
- 三欄全部符合才判定既有學員。
- 性別或出生日期缺少、姓名或任一欄不同時分類為新增。
- 同檔案相同空白 ID 身分鍵會阻擋。

### 預覽與服務測試

- 唯一符合時分類為更新並顯示目標 ID。
- 無符合時分類為新增及自動配號。
- 多人符合時產生阻擋錯誤。
- 報名新增／更新數量使用解析後的有效學員 ID 計算。
- 預覽 payload 不會把空白 ID 改寫成快照中的 ID。
- RPC 參數、回傳資料及錯誤訊息轉換正確。

### 元件測試

- 編輯表單的 ID 欄位可編輯。
- 非法 ID 顯示行內錯誤且不呼叫 RPC。
- ID 變更時顯示確認，取消時不儲存。
- 儲存成功後目前選取學員改用新 ID。
- 重複 ID 顯示指定中文錯誤。
- 手動新增學員使用相同數字規則。
- 匯入預覽顯示更新／新增數量及空白 ID 解析結果。

### 資料庫 pgTAP

- 修改學員 ID 後，所有 enrollment 外鍵同步更新且 course 不遺失。
- 目標 ID 已存在時整筆 rollback。
- 既有非數字 ID 可更新其他欄位，但改號必須使用數字。
- CSV 空白 ID 唯一符合時更新原學員，學生總數不增加。
- CSV 空白 ID 無符合時取得下一個數字 ID。
- CSV 空白 ID 多人符合時整批 rollback。
- 同檔案重複身分鍵整批 rollback。
- 非法指定 ID 被拒絕；前導零指定 ID 會正規化。
- 既有匯入授權、日期驗證、季度唯一性、課程取代與交易回滾測試持續通過。

## 驗收條件

- 使用者能在一般學員編輯視窗修改 ID。
- 修改成功後，畫面、學生資料、報名及課程仍指向同一位學員。
- 重複 ID 不會合併資料，並顯示明確錯誤。
- 所有新輸入或修改的 ID 都是正整數且沒有前導零。
- 既有非數字 ID 在未改號時仍可維護其他資料。
- 空白 CSV ID 的唯一三欄符合會更新既有學員；無符合才新增。
- 多人符合或同檔案重複時，不會寫入任何部分資料。
- 預覽與資料庫最終結果採用相同規則，資料庫仍是最終判定者。
