# 指定學員編號匯入設計

## 目標

季度 CSV 匯入時，若列中提供「學員編號」，系統應以該編號為準：資料庫已有該學員時更新資料；不存在時直接以該編號建立學員。這使首次匯入能保留來源編號，也使後續匯入可更新同一位學員。

## 範圍

只修改 `public.import_season_data(jsonb)` 的指定編號處理邏輯，並新增對應資料庫測試與 migration。CSV 表頭、前端預覽、資料表結構、RLS 與未填編號時的自動編號規則均不變。

## 行為

- 有指定編號且資料庫存在：更新學員資料與該季度報名資料。
- 有指定編號但資料庫不存在：以指定編號新增學員，再新增該季度報名資料。
- 未填編號：沿用目前的重複身分檢查與自動指派編號。
- 同一份 CSV 內出現重複的指定編號：維持阻擋匯入並回報錯誤，避免後列覆寫前列。

## 資料與錯誤處理

指定編號新增的數量計入 `students_inserted`；既有編號更新的數量計入 `students_updated`。既有的姓名、日期、季度、報名類型與課程驗證持續生效。移除 `ROW_<row>:STUDENT_ID_NOT_FOUND:<id>` 這個指定編號不存在時的拒絕條件。

## 驗證

資料庫測試應涵蓋：指定編號不存在時成功建立、同一編號再次匯入時更新、同檔重複指定編號仍失敗。部署前先執行 migration dry-run，再套用 migration，並以 RPC 讀回結果驗證新增與更新計數。
