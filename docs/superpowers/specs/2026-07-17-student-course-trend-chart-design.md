# 學生選課趨勢圖設計規格

## 目標

在學生詳細資料的 modal 中加入「學生選課趨勢圖」，讓使用者快速看出該學生最常選擇哪些課程，以及每門課實際出現在哪些季度。

## 已確認需求

- 採用橫向長條排行，不使用圓餅圖或季度堆疊圖。
- 圖表放在「歷年紀錄」內容頂端、既有選課時間軸之前。
- 每門課顯示課程名稱、有效選課次數及實際季度。
- 同一門課跨不同季度選修時累計次數。例如某課出現在三季，顯示 3 次。
- 同一門課在同一季度只計算一次，避免重複課程資料灌高次數。
- 已退費的 enrollment 不納入統計，也不顯示在該門課的季度標籤中。
- 沒有有效課程時顯示「尚無選課趨勢資料」。
- 圖表需在桌面與手機寬度的 modal 內正常顯示。

## 畫面設計

圖表區塊標題為「學生選課趨勢圖」。每一列包含：

1. 課程名稱。
2. 相對於最高次數的橫向長條。
3. 明確的「N 次」文字，避免只靠長條判讀。
4. 按季度先後排列的季度標籤，標籤沿用 enrollment 的 `season` 顯示值，例如「第十五季」。

課程依有效選課次數由多至少排列；次數相同時以課程名稱做穩定排序。所有課程都顯示，不設定前幾名截斷。季度標籤可自動換行，長課名及多個季度不得撐出 modal。

## 元件與責任

### 趨勢資料整理函式

建立獨立、無副作用的資料整理函式，接收目前學生已篩選的 enrollment timeline，輸出每門課的名稱、次數、季度清單及相對長條比例。它負責：

- 排除 `refunded` 為真值的 enrollment。
- 忽略空白課程名稱，並在比對前移除名稱前後空白。
- 以修整後的完整課名做精確比對，不自行合併名稱不同的課程。
- 在同一季度內將相同課程去重。
- 以既有季度比較邏輯排列每門課的季度。
- 依次數與課程名稱排列最後結果。

### `StudentCourseTrend` 顯示元件

建立專責顯示橫向長條圖的元件。元件只接收 timeline，不查詢資料庫、不修改資料；因此可獨立測試，也不影響既有新增、編輯或刪除 enrollment 的流程。

### `StudentDetailModal` 整合

沿用 `StudentDetailModal` 既有的 `studentTimeline`，確保資料已依 `student_id` 篩選。趨勢圖插入 tabbed 與 non-tabbed 兩種歷年紀錄版面，並置於 `EnrollmentTimeline` 之前。

## 資料流程

`enrollments` 先由 `StudentDetailModal` 依目前 `student_id` 篩選並排序，形成 `studentTimeline`；該 timeline 同時傳給趨勢圖與既有時間軸。趨勢元件在前端即時計算統計，不新增資料表、RPC、網路請求或套件依賴。當新增、編輯、刪除或退費狀態更新後，既有 refresh 流程更新 enrollments，圖表隨 props 重新計算。

## 空資料與異常資料

- timeline 為空、全部 enrollment 已退費，或所有有效 enrollment 都沒有課程時，顯示空資料訊息。
- 缺少 `courses`、`season` 或含空白課名時，不讓元件拋出錯誤；無有效課名的項目不計入。
- 若有效課程缺少季度文字，該次選課仍可納入次數，但不建立空白季度標籤。

## 可及性與樣式

- 每列提供可直接閱讀的課名與次數，不以顏色作為唯一資訊來源。
- 長條使用現有主題色與 CSS 變數，避免引入新的圖表套件。
- 圖表使用一般 HTML 與 CSS，季度標籤使用可換行的 flex 版面。
- 窄螢幕下課名、次數與季度區改為直向排列，保持文字可讀。

## 測試策略

- 先為資料整理函式新增失敗測試，再實作統計邏輯。
- 驗證跨季度累計、同季度去重、退費排除、空白課名忽略與排序。
- 驗證元件顯示標題、課名、次數、季度標籤及空資料訊息。
- 驗證 modal 只統計目前 `student_id` 的資料，且趨勢圖位於歷年紀錄中。
- 執行相關 Vitest 測試與正式 build，確認沒有破壞既有學生詳細資料功能。

## 不在本次範圍

- 點擊長條進行篩選或鑽取。
- 依年份切換、日期篩選或匯出圖表。
- 全體學生課程偏好比較。
- 新增第三方圖表套件或資料庫統計 API。
